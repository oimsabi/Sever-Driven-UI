# Server-Driven UI — หน้าเว็บอธิบายหลักการทำงาน

หน้าเว็บภาษาไทยที่อธิบายแนวคิด **Server-Driven UI (SDUI)** ด้วยแอนิเมชันแบบโต้ตอบได้
เขียนด้วย HTML + CSS + JavaScript ล้วน **ไม่มีไลบรารีหรือ build step**

เปิดใช้งานได้ทันทีโดยดับเบิลคลิกไฟล์ `index.html`
(หรือรัน `python3 -m http.server` แล้วเข้า `http://localhost:8000`)

---

## เนื้อหาในหน้าเว็บ

| # | หัวข้อ | สิ่งที่แสดง |
|---|--------|-------------|
| 01 | **แนวคิด** | เทียบ Client-Driven UI กับ Server-Driven UI พร้อมตัวอย่าง payload ของทั้งสองแบบ |
| 02 | **เปรียบเทียบ** | แอนิเมชัน "แข่งกัน" ระหว่างรอบ release ผ่าน App Store กับการ deploy config — เห็นชัดว่าฝั่ง SDUI ถึงมือผู้ใช้ก่อนหลายวัน |
| 03 | **ขั้นตอนการทำงาน** | แผนภาพ SVG 5 ขั้น มี packet วิ่งไปตามเส้นจริง ๆ (Client → BFF → CMS/DB → JSON → เรนเดอร์) เล่นอัตโนมัติหรือกดทีละขั้นได้ |
| 04 | **JSON → UI** | ไล่แปล JSON ทีละบรรทัด ไฮไลต์แถวใน Component Registry ที่ถูกเปิด แล้ววาด component ลงหน้าจอจำลอง รวมถึงเคส type ที่แอปไม่รู้จัก |
| 05 | **Playground** | แก้ JSON ได้เอง แล้วหน้าจอมือถือเรนเดอร์ใหม่ทันที มี preset ให้ลอง 4 แบบ |
| 06 | **อัปเดตทันที** | แผงควบคุมฝั่งเซิร์ฟเวอร์ + มือถือผู้ใช้ กด deploy แล้วกด "ผู้ใช้เปิดแอป" เพื่อเห็น UI เปลี่ยนโดยที่แอปยังเป็น v1.0.0 ตัวเดิม |
| 07 | **ข้อดี/ข้อเสีย** | สิ่งที่ได้ สิ่งที่ต้องแลก ควรใช้เมื่อไหร่ และกับดัก 6 ข้อที่ต้องออกแบบเผื่อไว้ |

## โครงสร้างไฟล์

```
index.html                 โครงหน้าและเนื้อหาทั้งหมด
assets/css/style.css       สไตล์ + คีย์เฟรมแอนิเมชันทุกตัว
assets/js/renderer.js      ตัวแปลง JSON → DOM (หัวใจของฝั่งไคลเอนต์ใน SDUI)
assets/js/main.js          ตัวควบคุมแต่ละส่วนของหน้า (race / flow / mapping / playground / OTA)
```

`renderer.js` แยกออกมาโดยตั้งใจ เพราะมันคือสิ่งเดียวกับที่แอปจริงต้องเขียนเป็น native code —
ส่วนที่เหลือของหน้าเว็บเป็นแค่ "เปลือก" ที่ใช้สาธิตมันจากหลาย ๆ มุม

## Component ที่ renderer รองรับ

`text` · `button` · `image` · `badge` · `rating` · `input` · `list` · `divider` · `spacer`
· `card` · `row` · `stack`

ถ้าเจอ `type` ที่ไม่มีในทะเบียน จะแสดงกล่อง fallback แทนการแครช —
ซึ่งเป็นพฤติกรรมบังคับของระบบ SDUI จริง เพราะแอปเวอร์ชันเก่าย่อมไม่รู้จัก component ที่เพิ่งเพิ่มบนเซิร์ฟเวอร์

ตัวอย่าง schema หนึ่งหน้าจอ:

```json
{
  "screenId": "product",
  "schemaVersion": 3,
  "components": [
    { "type": "image",  "label": "👟", "height": 130 },
    { "type": "badge",  "tone": "danger", "value": "ลด 20%" },
    { "type": "text",   "variant": "title", "value": "รองเท้าวิ่ง Aero X" },
    { "type": "rating", "value": 4.5, "count": 218 },
    { "type": "button", "tone": "primary", "value": "ซื้อเลย",
      "action": { "kind": "addToCart", "id": 8823 } }
  ]
}
```

## การเปิดหน้าเว็บผ่าน GitHub Pages

มี workflow `.github/workflows/deploy-pages.yml` เตรียมไว้แล้ว
เมื่อ Pages ถูกเปิดใช้งาน เว็บจะอยู่ที่ **https://oimsabi.github.io/Sever-Driven-UI/**

ต้องตั้งค่าในหน้า Settings ของ repo หนึ่งครั้งก่อน (สั่งจาก workflow ไม่ได้):

1. **Settings → Pages → Build and deployment → Source: `GitHub Actions`**
2. ไปที่แท็บ **Actions** แล้วกด **Re-run jobs** ที่ run ล่าสุด

> **ข้อจำกัด:** ตอนนี้ repo เป็น **private** ซึ่ง GitHub Pages ใช้ได้เฉพาะบัญชี
> GitHub Pro / Team / Enterprise เท่านั้น ถ้าเป็นบัญชี Free ต้องเปลี่ยน repo เป็น
> **public** ก่อน (Settings → General → Danger Zone → Change visibility)
> จึงจะเปิด Pages ได้

ทุก path ในหน้าเว็บเป็น relative จึงเสิร์ฟจาก subpath `/Sever-Driven-UI/` ได้เลยโดยไม่ต้องแก้อะไร

## แนวทาง Mobile / Tablet first

CSS เขียนแบบ mobile-first ทั้งไฟล์ — สไตล์พื้นฐานคือมือถือแนวตั้ง
แล้วค่อยเพิ่มด้วย `min-width: 640px` → `900px` → `1200px`

สิ่งที่ปรับให้มือถือเป็นหลัก ไม่ใช่แค่ย่อของเดสก์ท็อป:

| เรื่อง | ทำอะไร |
|---|---|
| **แผนภาพหัวข้อ 03** | สร้างด้วย JS จากข้อมูลชุดเดียว แล้ววางผังใหม่ตามจอ (มือถือ = เรียงลงแนวตั้ง viewBox แคบ / จอกว้าง = เรียงแนวนอน) เดิมเป็น SVG ตายตัวกว้าง 960 พอย่อลงมือถือตัวอักษรเหลือ ~4px |
| **ลำดับการอ่าน** | บนมือถือ จอมือถือจำลองถูกตรึงไว้บนสุดในหัวข้อ 04–06 และยกปุ่มควบคุมขึ้นมาชิดกัน เพื่อให้ "กดแล้วเห็นผลทันที" ไม่ต้องเลื่อนขึ้นลง |
| **พื้นที่กด** | ทุกปุ่ม/ลิงก์/สวิตช์อย่างน้อย 44×44px บนจอสัมผัส |
| **ช่องกรอก** | ใช้ฟอนต์ 16px บนอุปกรณ์สัมผัส เพื่อไม่ให้ Safari บน iOS ซูมหน้าจอเข้าเองตอนโฟกัส |
| **hover** | กฎ `:hover` ทั้งหมดอยู่ใน `@media (hover: hover) and (pointer: fine)` เพราะบนจอสัมผัสเบราว์เซอร์จะค้างสถานะ hover ไว้หลังแตะ ทำให้ปุ่มที่ไม่ได้เลือกดูเหมือนถูกเลือก |
| **แยกตามอุปกรณ์ ไม่ใช่ความกว้าง** | iPad Pro กว้าง 1024px แต่เป็นจอสัมผัส การย่อฟอร์มจึงผูกกับ `pointer: fine` ไม่ใช่ `min-width` |
| **จอเตี้ย** | มือถือ/แท็บเล็ตแนวนอน (สูง < 600px) จอจำลองเปลี่ยนเป็นแบบ "หน้าต่าง" กว้างแต่เตี้ย ไม่ยึดสัดส่วน 9:17.5 |

ทดสอบด้วย Chromium จริงที่ 375 / 390 / 640×420 / 768 / 1024 / 1440
ครบทุกขนาด: ไม่มี error, ไม่มีการเลื่อนแนวนอน, ไม่มีพื้นที่กดต่ำกว่า 44px,
ไม่มีช่องกรอกที่ทำให้ iOS ซูม, ตัวอักษรและบล็อกใน SVG ไม่ล้นกล่อง

## หมายเหตุด้านการเข้าถึง

- มีปุ่ม **แอนิเมชัน: เปิด/ปิด** บนแถบนำทาง (จำค่าไว้ใน `localStorage`)
  บนมือถือข้อความจะถูกซ่อน ไอคอนจึงสลับ 🎬 / ⏸ ตามสถานะ
- เคารพ `prefers-reduced-motion` ของระบบเป็นค่าเริ่มต้น
- รองรับจอตั้งแต่ 320px ขึ้นไป ไม่มีการเลื่อนแนวนอน
